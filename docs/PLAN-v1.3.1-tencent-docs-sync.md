# 收益报表同步到腾讯文档 · 可行性方案（v1.3.1）

> 关联：[收益记账规划](PLAN-v1.3-bookkeeping.md)、[验收指南](ACCEPTANCE-v1.2.md)
> 状态：**A 版（开发者账号建表 + 链接可读）已接入小程序**：云函数 `docsReport` 已部署，账本页可一键生成腾讯文档报表并跳转腾讯文档小程序。B 版（每个用户自己的文档）待 `client_secret` + 回调页。准备清单见 [TENCENT-DOCS-SETUP.md](TENCENT-DOCS-SETUP.md)。
> 结论：**能结合，但要分两条路线**——「导出导入」今天就能做；「每个用户绑定自己的腾讯文档」需要腾讯文档开放平台/API 权限，能否用个人主体开通需实际申请确认。

---

## 1. 先说结论

| 路线 | 能力 | 前置条件 | 建议 |
|---|---|---|---|
| A. 报表导出（CSV/TSV/Excel） | 一键复制表格文本 / 分享文件，用户粘到腾讯文档 | 无，纯本地 | **先做，1~2 人日** |
| B. 个人 Token 绑定（快速验证版） | 用户粘贴自己的腾讯文档 Token + 文档链接，云函数写表 | 用户能拿到个人 Token | 想快速验证时做，3~4 人日 |
| C. OAuth 正式绑定（产品级） | 用户在腾讯文档授权页授权，绑定自己的文档，之后一键同步 | 开放平台应用注册 + 审核 + OAuth 回调域名 | 体验最好，5~7 人日 + 审核周期 |

> 关键事实：腾讯文档开放平台有 OpenAPI（OAuth2 + `docs.qq.com/open/document/app/openapi/v2`），并提供**个人 Token**获取页（`docs.qq.com/open/auth/mcp.html`，QQ/微信登录即可生成）。开放平台接入流程是「注册/登录 → 选择主体类型 → 提交审核 → 发布上线」；个人主体能否通过审核、OAuth 回调限制如何，需要实际去申请确认。
> 参考：[腾讯文档开放平台](https://docs.qq.com/open/developers/)、[个人 Token 页](https://docs.qq.com/open/auth/mcp.html)、[OpenAPI v2 文档](https://docs.qq.com/open/document/app/openapi/v2)。

---

## 2. 路线 A：报表导出（推荐先做）

### 能做什么

- 账本页「导出报表」：
  - **复制表格文本（TSV）**：用户打开腾讯文档在线表格，直接粘贴即自动分列；
  - **分享 CSV/Excel 文件**：生成文件后用 `wx.shareFileMessage` 发到微信文件传输助手/好友，再在腾讯文档「导入」；
  - 导出范围跟随当前筛选（角色/工具/周期）。
- 表字段（与账本一致）：

```
结算时间 | 角色 | 工具 | 等级 | 完成环数 | 投入(万) | 产出(万) | 净收益(万) | ROI | 净收益率 | 用时(分) | 时薪(万) | 备注
```

- 追加一行「汇总」：总投入/总产出/净收益/平均ROI/轮次数/正收益率。

### 优点

- 今天就能用：不依赖任何第三方 API、无审核、无 token、无服务器成本；
- 每个用户天然“同步到自己的腾讯文档”（用户自己粘贴/导入一次）。

### 缺点

- 后续新数据需要再次导出/粘贴（不是自动同步）。

**工作量：1~2 人日**（含账本页按钮、TSV 复制、CSV 生成与文件分享、验收用例）。

---

## 3. 路线 B：个人 Token 绑定（快速验证）

### 用户流程

1. 账本页 →「绑定腾讯文档」；
2. 小程序内说明并引导复制链接，用户在浏览器打开 `docs.qq.com/open/auth/mcp.html`，QQ/微信登录 → 生成个人 Token；
3. 回小程序粘贴 Token + 粘贴自己的腾讯文档/在线表格链接；
4. 云函数校验（读文档信息）→ 保存绑定（Token 加密、docId/sheetId）；
5. 之后账本页「同步到腾讯文档」→ 云函数把报表写入该表格。

### 技术要点

- 云函数新增：`docsBind`（校验 token/文档、保存）、`docsSync`（组装行、写表格、去重）、`docsUnbind`；
- 存储：云数据库 `user_docs_binding`（按 openid 唯一），Token 用云函数环境变量里的密钥 AES-256-GCM 加密，**绝不下发到客户端**；
- 写入：优先「追加行 + runId 去重」（新增内部列 `runId`，同步前先读已有行），也支持「每次覆盖」模式（简单但会清空用户手改内容）；
- 所有调用在云函数完成，API 只有少量请求；小程序端只传报表数据。

### 风险（必须提前告知用户）

- **Token 是全量文档权限**：等于把用户腾讯文档访问权交给本应用，必须加密存储、支持随时解绑/撤销、写进隐私政策；
- Token 页面是面向 MCP/Skill 的入口，长期稳定性未知，可能变更；
- 腾讯文档 API 有免费额度（约 2 万次/应用，超出可能收费），每次同步消耗 1~3 次调用；
- 用户操作门槛高（复制 Token + 文档链接），体验一般。

**工作量：3~4 人日**（含绑定页、云函数、加密、同步、错误处理、隐私更新、验收）。

---

## 4. 路线 C：OAuth 正式绑定（产品级）

### 用户流程

1. 账本页「绑定腾讯文档」→ 跳转腾讯文档授权页（OAuth2）；
2. 用户同意授权 → 回调到我们的 H5 页面 → 云函数用 code 换 access/refresh token；
3. 用户选择「新建报表文档」或「绑定已有文档」（粘贴链接/选择）；
4. 之后一键同步，Token 自动刷新。

### 前置条件（需要你先确认）

- 腾讯文档开放平台注册应用，拿到 AppID/Secret；**主体类型审核**（个人/企业以平台审核为准）；
- OAuth 回调地址：需要自己的 HTTPS 域名（备案 + 小程序业务域名配置）；
- 小程序内 web-view 打开第三方 OAuth 页可能受业务域名限制，可能需要「外部浏览器授权 + 回填绑定码」的折中流程；
- API 权限范围（文档读写）、额度与收费政策。

### 技术要点

- 云函数：`docsOauthStart`（生成授权链接/state）、`docsOauthCallback`（H5 回调换 token）、`docsBindDoc`、`docsSync`、`docsUnbind`；
- 刷新 token 定时/惰性刷新；Token 加密存储；
- 写入策略同路线 B（追加去重/覆盖）。

**工作量：5~7 人日 + 审核等待**；如果审核不通过，就退回 A/B。

---

## 5. 数据与写入设计（B/C 共用）

### 报表结构

- 在线表格 Sheet「轮次明细」：列同上；或两张 Sheet：「汇总」「轮次明细」；
- 建议每行带隐藏列 `runId`（本地 `tool_id`），同步时先读 `runId` 列做去重；
- 同步记录：`lastSyncAt`、`lastSyncCount`、失败原因，展示在账本页。

### 同步模式

| 模式 | 行为 | 适用 |
|---|---|---|
| 追加（默认） | 只写入本地新增轮次，按 runId 去重 | 用户会手改表格/持续记账 |
| 覆盖 | 清空数据区后重写全部 | 只要报表、不要手改 |

### 安全

- Token 加密存储（密钥在云函数环境变量，不进代码仓库）；
- 解绑即删除 token；提供「撤销授权」说明；
- 隐私政策新增：收集腾讯文档授权信息及用途；
- 日志不打印 token/文档内容。

## 6. 建议实施顺序

1. **P3.1（先做）**：账本报表导出（TSV 复制 + CSV/文件分享）+ 验收用例、README/验收文档更新；1~2 人日。
2. **P3.2（先验证资质）**：你去腾讯文档开放平台申请/确认个人主体能否注册应用与 API 权限；
   - 能 → 走 OAuth 正式绑定；
   - 不能/等审核 → 先用个人 Token 绑定验证需求，或只保留导出。
3. **P3.3**：真机验证 + 腾讯文档实际写入测试（新建一张测试表，不碰用户正式文档）。

---

## 7. 需要你确认

1. **路线选择**：先做 A（导出）保底，还是直接冲 B（Token 绑定）/ C（OAuth）？
2. **腾讯文档资质**：你能用个人主体在腾讯文档开放平台注册应用吗？如果已有 AppID/Secret 最好。
3. **同步形态**：追加新轮次（推荐）还是每次覆盖整张表？
4. **报表范围**：同步「当前筛选结果」还是「当前角色全部已记账轮次 + 汇总」？
5. **文档由谁建**：应用自动建一张新表（返回链接），还是用户绑定已有表？
6. **Token 接受度**：如果走 B，用户需要自己复制 Token（全量权限），你能接受这个体验和风险提示吗？
