# 收益中心 MVP 方案（v1.5 提案）

> 状态：方案确认稿，先不改代码；等 v1.4.2 提审/发布后再进入开发，避免把未完成功能混进审核包。
> 目标：把「收益账本」从跑环专属，扩展成**全玩法收益记录 + 对比 + 报表**的独立栏目。

---

## 1. 结论

- **值得做独立栏目**：现有账本、图表、分享海报、腾讯文档报表可以直接复用，增量成本不高。
- **先做 MVP，不做大而全**：通用活动快速记账 + 宠环/人环自动汇入 + 活动时薪排行 + 周期汇总。
- **不建议一上来做第 5 个底部 Tab**：先用首页入口 + 独立页面验证使用率；数据证明「多玩法记录」成立后，再升级成 Tab（首页 / 宠环 / 人环 / 收益 / 我的）。
- **核心用户**：五开、搬砖、效率党；不是全体休闲玩家。

---

## 2. 用户与场景

### 2.1 五开 / 搬砖

- 今天抓鬼、师门、副本、宝图各刷了多久，哪个时薪最高？
- 五个号合计今天/本周净收益多少？
- 这个月点卡、旗子、药品成本占多少？
- 下周要不要把时间从抓鬼挪到副本？

### 2.2 单开效率党

- 今天到底赚了多少，值不值得继续？
- 抓鬼和师门哪个更适合我的等级？
- 月度收益能不能导出来看趋势？

### 2.3 内容创作者 / 队长

- 生成一张收益海报发群里；
- 导出腾讯文档给队友看；
- 记录本周活动安排和实际收益对比。

---

## 3. 栏目定位与入口

### 3.1 名称

对外统一叫「收益中心」，不叫「赚钱/提现」，避免审核风险。

### 3.2 入口（MVP）

- 首页「全部工具」宫格：把「奖励记录」替换为「收益中心」（奖励记录仍可在人环页查看）
- 收益账本页顶部增加「全部收益 ›」入口
- 我的页收益账本大栏目保持现状

### 3.3 后续

当「多玩法记录」周活用户达到一定量（例如 ≥30% 用户一周记 ≥5 笔），再把收益中心提升为第 5 个底部 Tab。

## 4. 页面结构

### 4.1 收益中心首页 `pages/profit/profit`

```
┌ 收益中心                          ┐
│ 所有玩法，一处记账                  │
│ [今日] [7天] [30天] [全部]          │
│                                     │
│ ┌ 本月净收益          1,234.5 万两 ┐│
│ │ 时薪 185.2 万/时 · 18.5 小时     ││
│ │ 共 42 笔 · 总投入 900 万两       ││
│ └──────────────────────────────────┘│
│                                     │
│ 活动排行（按净收益）                 │
│ 抓鬼     █████████  520 万  / 180万时薪
│ 副本     ██████     310 万  / 195万时薪
│ 宠环     ████       180 万  / 130万时薪
│ 师门     ██          95 万  / 78万时薪
│                                     │
│ 最近记录                             │
│ 10-23 抓鬼  30分钟  净 92 万  时薪184万
│ 10-23 师门  10分钟  净 13 万  时薪78万
│                                     │
│        [ + 记一笔 ]                  │
└─────────────────────────────────────┘
```

**空状态**：一张说明卡 + 「记第一笔」按钮 + 「去跑环账本」链接。

**列表**：默认 20 条/页，支持「加载更多」；左滑或长按删除（二次确认）。

### 4.2 快速记一笔（底部弹层）

字段：

| 字段 | 形式 | 说明 |
|---|---|---|
| 活动 | 横向 chips | 抓鬼 / 师门 / 副本 / 宝图 / 摆摊 / 其他 |
| 角色 | 当前角色，只读 | MVP 只记当前角色 |
| 时长 | 快捷 10/30/60/90 分钟 + 自定义 | 默认 30 |
| 现金收入 | 数字（万两） | 游戏币/现金 |
| 物品收入 | 数字（万两） | 可按参考价估，MVP 手填 |
| 成本 | 数字（万两） | 点卡/旗子/药/耐久合计 |
| 备注 | 单行文本 | 可选 |
| 实时预览 | 净收益 / 时薪 | 输入时更新 |
| 保存 | 主按钮 | 写入本地 |

> 不做「跑环」手动选项：跑环数据由宠环/人环助手自动汇入，避免重复记两遍。

### 4.3 记录详情 / 编辑

- 点击记录打开底部弹层，可改时长、收入、成本、备注
- 删除走二次确认；记录类操作支持撤销（复用 UndoStack 思路）

### 4.4 报表入口（MVP 后置）

- 第一版先复用现有「分享海报 / 腾讯文档」能力，增加「按活动拆分」
- MVP 页面先放一个「生成报表」占位按钮，等数据结构稳定后接

## 5. 数据模型

### 5.1 存储

- 按角色隔离：`mhxy_profit_<uid>`，JSON 数组
- 内部金额单位统一为「两」，展示时转「万两」
- 单条记录：

```js
{
  id: 'p_169..._xxx',
  source: 'manual',          // manual | pet | chain
  sourceId: '',              // 自动汇入时存 run id，防重复
  activity: 'ghost',         // 见 ACTIVITIES
  activityLabel: '抓鬼',
  roleId: 'user_xxx',
  roleName: '角色A',
  startedAt: 1792684672311,  // 开始时间（排序/周期过滤）
  durationMin: 30,           // 有效时长（分钟）
  cashIncomeLiang: 800000,
  itemIncomeLiang: 200000,
  costLiang: 80000,
  note: '',
  createdAt: 1792684672311
}
```

### 5.2 派生字段（不存储，计算得出）

- `income = cashIncomeLiang + itemIncomeLiang`
- `net = income - costLiang`
- `hourly = net / (durationMin / 60)`
- `roi = costLiang > 0 ? income / costLiang : null`
- `netRate = costLiang > 0 ? net / costLiang : null`

### 5.3 活动枚举

```js
ACTIVITIES = [
  { key: 'ghost',   label: '抓鬼', icon: '👻' },
  { key: 'school',  label: '师门', icon: '🏫' },
  { key: 'dungeon', label: '副本', icon: '🏯' },
  { key: 'treasure',label: '宝图', icon: '🗺️' },
  { key: 'stall',   label: '摆摊', icon: '🏪' },
  { key: 'other',   label: '其他', icon: '📦' }
]
```

> 宠环/人环不放进手动枚举，作为自动来源单独显示。

### 5.4 汇总函数（`utils/profit.js` 纯函数）

- `summarize(records, { period, now })`：净收益、总成本、总时长、时薪、笔数、ROI
- `rankByActivity(records, { period, now })`：按活动聚合净收益/时薪/时长，按时薪或净收益排序
- `filterByPeriod(records, period, now)`：今日 / 7 天 / 30 天 / 全部
- `normalizeRecord(input)`：校验、转数字、补默认字段
- `mergeRunRecords(manual, petRuns, chainRuns)`：把宠环/人环 run 映射成 source 记录（防重复）

### 5.5 自动汇入宠环/人环

- 只取 `LEDGER.isBooked(run)` 的已记账轮次
- 映射：
  - `source: 'pet' | 'chain'`
  - `activityLabel: '宠环' | '人环'`
  - `startedAt: run.doneAt || run.startedAt`
  - `durationMin: run.durationMin`
  - `cashIncomeLiang`：暂无（0），`itemIncomeLiang: run.income`
  - `costLiang: LEDGER.runCost(run)`
- 用 `sourceId` 去重，避免重复展示

### 5.6 与现有账本的关系

- 收益中心是**统一入口**，收益账本是**深度明细**（逐轮成本/收益/ROI/图表）
- 从收益中心点活动行 → 跳到账本对应筛选，或打开轮次明细
- 数据来源保持单一：跑环走运行数据，其他玩法走手动记录，不重复计算

## 6. 周期与指标口径

- 周期：今日（自然日）、近 7 天、近 30 天、全部
- 净收益：产出 - 成本（手动记录成本包含点卡/消耗；跑环沿用账本口径）
- 时薪：净收益 ÷ 有效工时
- ROI：产出 ÷ 成本；成本为 0 时显示「—」
- 笔数：手动记录 + 已记账跑环轮次
- 所有展示标注「估算」，避免用户当成精确财务数据

---

## 7. MVP 不做清单

- 不做库存/摆摊卖出结算
- 不做全物品价目表（先手填物品收入）
- 不做五开分组/角色分摊（先当前角色）
- 不做自动读取游戏数据/脚本
- 不做独立分享海报（先复用现有报表能力）
- 不做第 5 个 Tab（先首页入口验证）

## 9. 验证指标

上线后看：

- 7 日内至少记录 3 笔的用户占比
- 有 ≥2 种活动记录的用户占比（验证“多玩法”需求是否真实）
- 活动排行/周期切换的使用率
- 分享/导出使用率

如果大多数用户只记 1 种活动、或只记一天，说明需求不成立，应停在跑环深度工具，不再扩全玩法。
