## 1. 一句话目标

把「只记成本」升级成「**成本 + 收益 + 投入产出比**」的完整账本：每轮跑完能记清投入多少、产出多少、净赚多少、划不划算，并能按时间/角色/工具汇总历史投入与轮次收益明细。

### 做什么

- 每轮结算时记录：成本明细（按任务类型）、收益明细（书铁/灵饰/战魄/修炼果等及其价值）、其他投入
- 自动计算：净收益、投入产出比（ROI）、时薪、用时
- 历史列表展示每轮投入/产出/净收益/ROI，点开可看明细、可补录/修改收益
- 新增「收益账本」页：按日/周/月/全部汇总总投入、总产出、净收益、ROI，含趋势图与轮次列表
- 奖励价目表（可按角色自定义），结算时自动带出参考价、可改实际价
- 旧数据兼容：未记账的历史轮次标记「未记账」，支持补录

### 不做什么（本期）

- 不做多端同步账本、不做云函数改动（现有备份会自动带上新字段）
- 不做交易/拍卖行数据抓取、不做自动识别游戏奖励
- 不做团队/多人账本

| 已有 | 位置/说明 | 缺口 |

## 3. 指标定义（口径先定死）

| 指标 | 公式 | 说明 |
|---|---|---|
| 投入（成本） | `cost = 任务物品成本之和 + 其他投入` | 任务物品成本沿用现有价格表；「其他投入」选填（旗子/时间成本等） |
| 产出（收入） | `income = Σ 奖励明细金额` | 金额来自奖励价目表（参考价）或用户填的实际价 |
| 净收益 | `profit = income - cost` | 可为负 |
| 投入产出比 ROI | `roi = income / cost` | 展示成「1 : 1.28」或「128%」；cost=0 时显示「—」 |
| 净收益率 | `netRate = profit / cost × 100%` | 与 ROI 同时展示，避免误读 |
| 用时 | `durationMin = round((doneAt - startedAt) / 60000)` | 小于 5 分钟或缺失时不算时薪 |
| 时薪 | `hourly = profit / (durationMin / 60)` | 单位：万两/小时 |
| 历史投入 | `Σ cost`（按筛选周期） | 未结算轮次单独展示，不混入 ROI |
| 平均每轮 | `Σ profit / 轮次数` | 只统计已记账轮次 |
| 正收益率 | `profit > 0 的轮次数 / 已记账轮次数` | 辅助指标 |

> 决策点：ROI 建议**同时展示**「产出/投入倍数」和「净收益率」，并标注口径，避免用户把 1:1.28 误读成赚 128%。

## 4. 数据模型

### 4.1 每轮记录（宠环 / 跑环共用字段）

```js
{
  // ===== 现有字段保持不变（兼容） =====
  id, level, startedAt, doneAt, done, level, rings, reward / rewards, totalCost,

  // ===== v1.3 新增 =====
  ledgerVersion: 1,
  costItems: [                      // 成本明细（结算时快照，历史不随改价变化）
    { tid: 'equip60', name: '60环装', qty: 3, unitPrice: 180000, amount: 540000 }
  ],
  extraCost: 0,                     // 其他投入（两）
  incomeItems: [                    // 收益明细（每项一个奖励）
    { kind: 'book', name: '150级制造指南书-剑', level: 150, subType: '剑', qty: 1, unitPrice: 50000000, amount: 50000000 },
    { kind: 'xiulian_guo', name: '修炼果', qty: 1, unitPrice: 500000, amount: 500000 },
    { kind: 'other', name: '自定义奖励', qty: 1, unitPrice: 200000, amount: 200000 }
  ],
  income: 50000000,                 // 产出（两）
  profit: 49600000,                 // 净收益
  roi: 1.08,                        // income / cost（仅展示用）
  netRate: 0.08,                    // profit / cost
  hourly: 6200000,                  // 万两/小时（可能为 null）
  durationMin: 48,
  pricedAt: 1792670000000,          // 估值时间
  unbooked: false                   // true = 旧数据未记账
}
```

- 跑环的 `incomeItems` 增加 `seg: 100 | 200 | 300`，用于分段展示。
- 宠环主奖励（书/铁/战魄）+ 额外奖励（修炼果/200修炼点/3级家具图）+ 自定义，全部拆成 `incomeItems`。
- 旧 `reward` / `rewards` 字段继续保留用于兼容展示；新逻辑以 `incomeItems` 为准。

### 4.2 奖励价目表（按角色）

新增 storage key：`mhxy_reward_prices_<uid>`（宠环、跑环共用一套）

```js
{
  version: 1,
  books:  { 80: 200000, 90: 350000, 100: 1000000, 110: 1500000,
            120: 4000000, 130: 10000000, 140: 20000000, 150: 50000000 },
  irons:  { 80: 120000, 90: 200000, 100: 600000, 110: 900000,
            120: 2400000, 130: 6000000, 140: 12000000, 150: 30000000 },
  zhanpo: 80000000,                       // 战魄
  lingshi: { 120: 3000000, 140: 12000000 }, // 灵饰指南书/元灵晶石，同价
  items: {
    xiulian_guo: 500000,     // 修炼果
    xiulian_200: 600000,     // 200修炼点（按修炼果折算）
    furniture3: 2000000      // 3级家具设计图
  }
}
```

- 默认值取 FAQ 中的参考区间中位（仅作初始值，结算弹窗可改），界面标注「参考价，可自行修改」。
- 支持「恢复默认」、导入/导出；换角色各自独立。

### 4.3 汇总计算位置

- 每轮 `income/profit/roi/...` 在**结算时**算好写入 `run`，历史稳定、不随改价变化。
- 账本页对 `runs` 做聚合（O(轮次)），数据量小，不额外建索引/缓存。
- 老数据（无 `income` 字段）视为未记账：计入「历史投入」，不计入产出/ROI，并进入补录列表。

## 5. 记账流程

### 5.1 结算时估值（宠环）

现有结算弹窗：选类别/等级/类型 → 主奖励文字；勾选额外奖励；自定义输入。
新增：

1. 选完奖励后自动带出「参考单价」（来自奖励价目表），旁边可编辑；
2. 额外奖励勾选时带出单价（可改）；
3. 自定义奖励输入名称 + 金额；
4. 弹窗底部实时汇总：`本轮收入 X 万 · 投入 Y 万 · 净收益 Z 万 · 投入产出比 1:N`；
5. 可选「其他投入」输入框（默认 0）；
6. 未选择任何奖励时允许结算，但标记 `unbooked: true`（之后可补录）。

### 5.2 结算时估值（跑环）

段奖励弹窗（100/200/300 环）同样加「单价/金额」字段；三段奖励的价值累计到 `incomeItems`；300 环若出灵饰/战魄，通过多选项处理。

### 5.3 历史补录/修改

- 历史列表每条增加「收益」状态：`已记账 / 未记账 / 手动修改`；
- 点开「明细」抽屉：
  - 上半：时间、角色、等级、环数、得分/奖励摘要、用时；
  - 成本区：按任务类型汇总（数量×单价=金额），可加「其他投入」；
  - 收入区：逐项奖励 + 金额，可编辑/删除/新增；
  - 底部：收入/投入/净收益/ROI/时薪；
  - 按钮：保存修改、按默认价补录（仅未记账）、删除本轮。
- 批量补录：历史页「按默认价补录全部未记账轮次」入口，二次确认后按奖励文字解析 + 默认价写入 `incomeItems`。

### 5.4 奖励文字解析规则（补录用）

- `150级制造指南书-剑` → `{kind:'book', level:150, subType:'剑'}`
- `140级百炼精铁` → `{kind:'iron', level:140}`
- `160级战魄` → `{kind:'zhanpo'}`
- `修炼果` / `200修炼点` / `3级家具设计图` → `kind: 'xiulian_guo' / 'xiulian_200' / 'furniture3'`
- 无法识别的文字 → `kind:'other'`，金额默认 0，列出待补价。

- 汇总卡：总投入、总产出、净收益、ROI、平均每轮、时薪、轮次、正收益率。

### 6.2 轮次明细抽屉（账本/历史共用）

- 摘要：角色、工具、等级、起止时间、用时、得分/奖励文字；

- 收入明细表：奖励项 × 单价 = 金额，合计；
- 指标行：净收益、投入产出比、净收益率、时薪；
- 操作：编辑（价目表式弹窗）、删除、关闭。

### 6.3 奖励价目表设置

- 入口：账本页右上角「⚙️ 价目表」、或宠物/跑环「⋯」菜单；
- 分组：制造指南书（80~150）、百炼精铁、灵饰、战魄、特殊奖励（修炼果/修炼点/家具图）；

- 恢复默认、导入/导出（复用现有剪贴板导入导出思路）。

### 6.4 原有统计页调整

- 宠物/跑环「统计」标签页保留现状，底部加「查看收益账本」按钮；
- 历史列表每条右侧增加「净收益/ROI」小字，点击进入明细抽屉。

## 9. 兼容与迁移

1. **旧轮次**：无 `incomeItems` → `unbooked: true`，产出按「—」展示；成本仍用历史 `totalCost`（已有）。
2. **补录**：历史/账本里对未记账轮次逐条或批量按默认价补录，补录后写 `ledgerVersion: 1`。
3. **云端备份**：`runs` 数组整体备份，新增字段自动包含，**syncUpload/syncDownload 不需要改**；单文档 900KB 限制已有提示。
4. **导出/导入**：JSON 直接包含新字段；导入旧 JSON 时缺字段按未记账处理。
5. **价格表**：首次进入账本/结算时若无 `mhxy_reward_prices_<uid>`，自动写入默认表并提示「已使用参考价，可到价目表修改」。
6. **不改数据结构字段名**：`totalCost` 保留；新增 `extraCost` 与 `cost` 分开存（`cost = totalCost + extraCost` 不重复存）。

## 10. 验收标准（DoD）

### 功能

- [ ] 宠环/跑环结算时可填奖励单价，实时显示收入/净收益/ROI
- [ ] 结算后 `run` 含 `costItems / incomeItems / income / profit / roi / netRate / durationMin / hourly`
- [ ] 历史列表显示每轮净收益与 ROI，点开有成本/收入明细
- [ ] 未记账旧轮次可单条/批量补录，补录后指标正确
- [ ] 账本页可按角色/工具/周期筛选，汇总卡与列表数字一致
- [ ] 累计净收益折线随筛选变化正确
- [ ] 奖励价目表可改、可恢复默认、按角色隔离
- [ ] 成本为 0、用时缺失、无奖励等边界不报错，显示「—」
- [ ] 导出→清数据→导入，账本数据一致

### 测试

- 单测（`tests/ledger.test.js` 等）：
  - ROI / netRate / hourly / duration 计算与边界；
  - 周期过滤（7天/30天/本月/全部）；
  - 多角色聚合；
  - 旧数据未记账识别与补录；
  - 奖励文字解析（书/铁/战魄/修炼果/未知）。
- 页面逻辑测试：结算后 run 字段、历史展示数据、账本聚合数据。
- 自动化：账本页可打开、筛选切换后卡片数字变化（原生 showModal 流程仍由单测覆盖）。

### 性能

- 1000 轮以内账本聚合 <100ms；页面 setData 不传整轮 rings（只传汇总/列表字段）。

## 12. 等你确认的 8 个口径问题

1. **收入口径**：结算时默认按「参考价」自动算，允许手动改成实际成交价——这个逻辑可以吗？还是只记实际价？
2. **其他投入**：是否需要「其他投入（万）」输入框（旗子、药、时间成本等）？默认 0。
3. **默认价目表**：上表的初始参考价是否可接受？如果你能给我区服常见价（80/100/120/140/150 书铁、修炼果、战魄、灵饰），我直接换成你的数据。
4. **统计范围**：账本默认只看当前角色，还是默认「全部角色」汇总？
5. **未结算/放弃轮次**：要不要单独展示「沉没成本」卡片？（建议只做展示、不算 ROI）
6. **ROI 展示**：同时显示「1:1.28（产出/投入）」和「净收益率 +28%」，可以吗？
7. **账本入口**：首页「收益统计」进入新账本页 + 宠物/跑环统计页加「查看账本」——够吗？还是把账本做成底部第 4 个 Tab？
8. **旧数据补录**：需要「一键按默认价补录全部未记账轮次」吗？（有误估值风险，默认逐条确认更稳）

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 奖励价不准导致收益失真 | 全部标注「参考价」；结算可改实际价；价目表可随时改，历史已记账值不被追溯 |
